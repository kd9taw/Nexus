# The libSystem functions and data the macOS app binary (Contents/MacOS/Nexus) imports STRONGLY.
# Each name here was reviewed against macOS 12 on 2026-10-31, the app's minimum macOS.
#
# scripts/check-macho-bundle.mjs --system-imports fails the release on any strong libSystem import
# of the app binary NOT on this list (release.yml runs it on both macOS legs before signing). C and
# C++ code reaches a function newer than the minimum only through a weak reference, which dyld
# leaves null on an older Mac; Rust has no availability annotations, so an `extern` binding to a
# newer libSystem function links as a strong reference and stops the app at launch on macOS 12
# ("Symbol not found"). This is the list of the ones that cannot do that.
#
# How the list was made and checked:
#   - The arm64 names are every strong import bound to /usr/lib/libSystem.B.dylib in the symbol
#     table of the 1.21.0 release's Apple Silicon app binary (Nexus_1.21.0_aarch64.app.tar.gz),
#     read with this script's own reader.
#   - The `$INODE64` names are the x86_64 spellings of the stat/statfs/opendir family that arm64
#     imports plainly: no Intel build has been released, so they were added from the arm64 names
#     whose x86_64 variant libSystem exports.
#   - Every name is exported by libSystem in the macOS 11.3 SDK (usr/lib/libSystem.B.tbd and the
#     usr/lib/system/*.tbd it re-exports) for the architecture that imports it, so it exists on
#     macOS 12.
#
# To add a name the check reports: confirm the app's minimum macOS exports it for that
# architecture (the SDK's .tbd files, or the API's availability in its header), add it in sorted
# order, and say in the commit how it was checked. One Mach-O symbol per line, as nm prints it.
