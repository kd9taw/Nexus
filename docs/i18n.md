# Translating Nexus

Nexus ships in English. This page is for contributors: how to add a user-visible string so it
*can* be translated later, and what must never be translated at all.

Right now the machinery is in place and nothing has changed on screen. Four files are migrated
out of about 250; everything else is still hardcoded English, and that is expected.

## Adding a string

Two steps, both in `ui/src`.

1. Put the English in `ui/src/i18n/en.ts`:

   ```ts
   'settings.station.callsign.label': 'Callsign',
   ```

2. Use it:

   ```tsx
   import { t } from '../i18n'

   <span className="settings-label">{t('settings.station.callsign.label')}</span>
   <input placeholder={t('settings.search.placeholder')} aria-label={t('settings.search.label')} />
   ```

`t()` returns a plain string, so it works for `title`, `placeholder`, `aria-label` and anything
else that needs one. Keys are typed — a key that is not in `en.ts` will not compile.

### Keys

`<area>.<surface>.<element>` — lowerCamel segments, dots between them.

A key names a *meaning*. It must not name the component it currently lives in, the tab it sits
on, or the English words it currently holds, because all three change and the key must not. If
you reword a string without changing what it means, edit the English in place and leave the key
alone. If the meaning changes, that is a new key: an old translation of a different meaning is
worse than falling back to English.

Never build a sentence out of several keys. Word order is not the same in every language, so a
sentence glued together from three pieces cannot be translated. One sentence, one key.

### Values in the middle of a sentence

`{{double braces}}`:

```ts
'settings.search.matched': 'matched “{{term}}”',
```
```tsx
t('settings.search.matched', { term: hit.matched })
```

Double braces, because single braces are already taken: `{NAME}`, `{MYSTATE}` and friends are
CW macro tokens that appear inside real hints and have to reach the operator untouched.

### Counts

Pass `count` and give the entry plural forms instead of a string:

```ts
'logbook.marked': { one: 'Marked 1 QSO', other: 'Marked {{count}} QSOs' },
```

Do not write `n === 1 ? '' : 's'`. English has two forms, Polish has four, Arabic has six, and
the ternary cannot express any of them. `Intl.PluralRules` picks the form; nothing has to be
configured per language.

### Bold, code, links inside a sentence

Use `<T>` and supply the elements yourself:

```tsx
import { T } from '../i18n/T'

<T k="reveal.prompt" tags={{ b: <strong /> }} vals={{ achievement, feature }} />
```
```ts
'reveal.prompt': '<b>{{achievement}}</b> — turn on <b>{{feature}}</b>?',
```

The markers in the catalog are names, not HTML. Only names you passed in `tags` become
elements; anything else stays literal text, so a catalog string can never introduce an element,
an attribute or an event handler. Values are substituted after the markers are parsed, so a
value that happens to contain `<b>` is text too.

## What is never translated

Nexus is a radio application, and most of what it puts on screen is not prose. Getting this
wrong is not a cosmetic bug: `14,074` is not `14.074`, and a decimal comma that reaches a dial,
a log or a CAT command puts a station somewhere it did not intend to be.

**Prose** — labels, hints, tooltips, buttons, error sentences, accessible names, and human
example values (a first name, "leave blank if that is you"). These go in the catalog.

**Technical tokens** — never translated, never locale-formatted, never in the catalog:

- frequencies and any number that is one: dial MHz, offsets, shifts, tone Hz, baud
- signal reports (599, −14 dB), power in watts, WPM
- callsigns, grid squares, DXCC prefixes, CQ/ITU zones, ARRL/RAC section codes
- band names (20m), mode names (FT8, USB, PSK31), Q-codes, RST, POTA/SOTA references
- ADIF field names (`OPERATOR`, `STATION_CALLSIGN`) and macro tokens (`{NAME}`, `{MYSTATE}`)
- the `value` of every `<select>`, every persisted key, every id — the label is prose, the
  value is a token, and they are not the same string
- example values drawn from any of the above (`KD9TAW`, `EN52xa`, `WI`)

In code that means: give the token a named constant, and never hand a number to
`toLocaleString()` on its way into a message. Numbers interpolated by `t()` are stringified
invariantly and cannot pick up a decimal comma, whatever the operating system's locale is.

## The guard

`ui/src/i18n/hardcoded-strings.test.ts` parses every migrated file and fails when a new
operator-visible string is hardcoded in one — JSX text, `title`/`placeholder`/`aria-label` and
friends, a string literal used as a child, or prose passed to `pushToast`. It only checks the
files on its `MIGRATED` list; that list grows as surfaces are migrated and is the honest
statement of what is covered.

If it fails on a string that is a technical token rather than prose, the fix is not to add it
to the catalog — it is to name it as a constant and say why.

## Adding a language (not yet)

When the time comes: write `ui/src/i18n/<locale>.ts` as a partial catalog with the same keys,
import it statically, and `installCatalog('de', DE)` at startup. Anything the file leaves out
falls back to English automatically, so a half-finished catalog is usable and never shows a key
or a blank control.

Catalogs are static imports on purpose. Nexus has to work with no network at all — a field day
site, a summit, a boat — so nothing about the interface may be fetched at runtime.

Two things still have to be built before a language can actually ship: a setting to choose one,
and a re-render when it changes (`units.ts` has the pattern — a window event plus a hook).

## Why there is no i18n library

The realistic options were react-i18next, LinguiJS and FormatJS/react-intl. All three are
capable and well maintained, and all three are built around machinery this application must not
use: catalog loaders and language detectors we would have to disable, and a copy of the plural
rules that the webview already has as `Intl.PluralRules`. Lingui and FormatJS additionally want
a Babel or SWC step in a build that has none.

What was left after removing the parts we cannot use was about 250 lines, so it is written out
in `ui/src/i18n/index.ts` instead of taken as a dependency. It gives us three things a library
would have made harder: keys checked by the TypeScript compiler with no code generation, a
fallback to English that is the ordinary code path rather than a configuration option, and a
runtime with no way to format a number at all.
